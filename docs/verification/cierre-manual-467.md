# Cierre manual sin bloqueo (#467)

El botón manual permite terminar aunque falten puntos, fotos o respuestas. El servidor fija guard_flow_completed en el mismo cierre, usa el cumplimiento real y conserva los faltantes. Una repetición o recuperación de un cierre anterior mantiene su hora y porcentaje. Se bloquea la fila y se comprueba guardia/tenant; una ronda pendiente sin iniciar sigue sin poder cerrarse. El recorrido libre también finaliza su flujo y el cierre manual solicita el despacho del informe.

La web conserva el control de término cuando una ronda cerrada aún tiene tareas visibles y permite finalizar desde el resumen con trabajo pendiente. Persiste la intención de sincronizar antes de pedir el cierre; volver al inicio no espera la carga de fotos. Lo capturado permanece durable. La recuperación de rondas anteriores obtiene primero un estado y escaneos autorizados por la API, activa su envío y sube las fotos conservadas aunque falte la respuesta. Solo retira las copias locales de fotos cuyo recibo ya tiene; no inventa respuestas. También recupera fotos de punto sin checklist y evita reenviar borradores cuyas fotos ya fueron recibidas. La ronda activa mantiene la carga diferida hasta la intención de cierre.

La confirmación automática y la exigencia de foto/tareas en el último punto siguen vigentes hasta que el usuario elija cerrar manualmente. No cambian el puente NFC, el GPS, las contraseñas o la sesión. La falta de conexión al solicitar cierre conserva el trabajo y permite reintentar.

Validación: regresiones API y web fallando antes y pasando después; 383 pruebas API y 84 web, tipos, lint y builds. PostgreSQL real: el código anterior conserva el bloqueo y el nuevo libera el inicio; el cierre repetido no cambia hora/cumplimiento ni duplica el despacho, y otro guardia recibe rechazo. Todas las filas de prueba se revierten. Navegador móvil: cierre ya incompleto con tareas/fotos pendientes, retorno al inicio sin esperar carga y reintento sin conexión; borrador conservado. La ronda real afectada se recuperó con su avance original, sin alterar evidencia.

El propietario autorizó publicar aun con rondas activas. Despliegue API/web desacoplado de SSH, con PostgreSQL y Redis conservados; no APK/AAB ni nuevas Actions. La asignación posterior de supervisores reutiliza las cuentas existentes y se registra en el expediente privado, sin publicar datos personales.
